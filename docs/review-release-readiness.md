# Public review release evidence

Checked 2026-09-06 against `dc75efe5ce87ffe3583657f91bda86b96bb4a812`, after #12. This is the bounded report for #16, not a production configuration change or a repository-wide vulnerability assessment.

**Decision: keep broader promotion and additional paid production exposure gated.** The current browser release is deployed and its deterministic checks pass. No exploitable advisory was demonstrated in the inspected text-review path, but the installed advisory baseline is unresolved and the provider's actual spending limit has not been verified. A per-IP firewall rule is not a global cost ceiling. These findings do not establish that the whole deployment is safe or unsafe.

[Vercel rule actions](https://vercel.com/docs/vercel-firewall/vercel-waf/custom-rules) distinguish logging from enforcement. The observed rule has an enforcing action, but one IP window does not cover distributed traffic or prove a monetary ceiling. The raw firewall response, account identifiers and environment metadata are deliberately not committed.

Review effective deployed rules and direct deployment-domain behavior. No production stress test or blind `/api/*` firewall change. Clearing this packet does not itself establish a dollar cap.
4. **Framework patch packet.** On a fresh isolated branch, verify the smallest currently supported fixed version for the demonstrated/current framework advisories; the fetched Next advisories name `16.2.11` as their fixed 16.x floor. The audit's aggregate suggestion is `16.3.4` because inherited findings also exist; it is not automatically the smallest required intervention. Add the failing synthetic regression for any trigger actually demonstrated; retain all review exports and MCP contracts. Do not claim a blanket clean audit or perform `npm audit fix --force`.

No runtime exploit was confirmed here, so there is no fabricated exploit-specific patch.
