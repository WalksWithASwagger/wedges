# Visual critique experiment — issue #15

## Work packet and decision

Goal: test a bounded still-image contract before any production visual review feature. Owned files are the experimental module, script, original fixtures/tests and this report. Production tool registration, UI, manifests, model defaults and existing records are unchanged. One offline PR completes #15's explicitly permitted offline boundary; it does **not** unlock #22.

Recommendation: **narrow and hold**. Mechanical boundaries are testable. Usefulness, photographic detail, injection resistance and claims about unseen footage remain unverified. No live model call, paid evaluation, private image or human author evaluation was performed. No semantic pass is claimed.

## Reproduce

```sh
npm run typecheck
npm test
npm run lint
node --import tsx scripts/eval-visual-critique.ts --offline
```

The harness defaults to offline even without a flag. Offline preflight prints byte counts and fixture names, never credentials or image payloads. Node tests use the actual installed AI SDK with a stubbed transport to verify the serialized request, token cap and no retries. Boundary tests cover corrupt/truncated/non-image input, unknown fields/IDs, duplicate IDs, invalid quotations, invalid output/status, missing credentials, cancellation, empty evidence and call exhaustion. A validator cannot establish whether an observation actually describes an image.

## Experimental constraints

- At most four stable, unique asset IDs (`[a-z0-9-]`, 1–40 characters). Optional labels are at most 120 characters and treated as untrusted author assertions. A contact sheet is one asset; its panels are not independently addressable assets.
- Only canonical base64, metadata-free, non-interlaced RGB8 PNG is accepted. No URLs, JPEG, SVG, GIF, alpha, color-profile, EXIF or ancillary chunks. PNG signature, chunk CRC, dimensions, decompression length and row-filter bytes are checked. This deliberately restricted parser is not a general production decoder. A future browser workflow must decode/re-encode selected files safely and test that boundary separately.
- Maximum 1024 × 1024 pixels and 700,000 decoded bytes per image; 4,000 taste characters. The complete serialized UTF-8 input and the **actual SDK-generated provider body**, including base64, schema and prompt overhead, must each fit 3,000,000 bytes. Four individually valid images can exceed the aggregate cap and must be rejected, not silently truncated.
- Strict response: zero to three suggestions. Each references supplied asset IDs, a nonempty exact taste substring, a visible observation and proposed action. Empty taste/images avoid a request and return `insufficient_evidence`; unrelated/ambiguous evidence is a model instruction and human gate. Schema-valid but semantically unsupported advice is still a failure.
- No production storage or portable-record format changes. Future #22 needs a separately reviewed versioned record carrying immutable selected-image bytes, ID/media type, author label, exact taste snapshot and separately editable author decisions. Existing v1 text-review imports must remain readable; do not silently add assets to v1. Any export envelope must account for base64 overhead and quota before saving. No external asset URL persistence or object store is proposed here.

## Fixture provenance and limits

All four PNGs are original synthetic drawings generated by `tests/fixtures/visual/generate.py` using Pillow, an optional fixture-authoring tool, not a runtime dependency. No downloaded, private, photographic or film work is included. Seven cases cover a **single-photo composition proxy**, four selected identical frame proxies, contact sheet, mismatched audio taste, ambiguous gray field, misleading filename/timecode and readable image-embedded instructions.

The proxies deliberately establish only transport and adversarial fixtures. They cannot establish photographic usefulness or frame selection quality. Before claiming feasibility, supplement with explicitly consented photography/selected frames held privately; record provenance and consent without committing private images. Do not count a proxy as a real-author study.

## Live harness safety and pending evidence

The CLI prints limits before checking credentials: fixed `claude-haiku-4-5-20251001`, at most eight attempted calls per process (currently seven cases), 1,200 maximum output tokens/call, zero retries, 45-second AbortSignal deadline/call. It requires `--live`, `--confirm-budget-usd=0.25` and `--docs-verified=YYYY-MM-DD` for today's UTC date. Flags acknowledge an authorization and documentation review; they do not grant permission. Missing credentials fail without a request. Do not use this command without explicit paid-eval approval:

```sh
# Only after spend approval and today's official documentation recheck:
varlock run --inject vars -- node --import tsx scripts/eval-visual-critique.ts --live --confirm-budget-usd=0.25 --docs-verified=YYYY-MM-DD
```

Estimated ceiling: **US$0.25/run**, based on a conservative 20,000 input tokens/call allowance (up to four 1024² images plus text/schema overhead), $1/M input and $5/M output: 8 × ($0.020 + $0.006) = $0.208, rounded upward. This is an estimate, not a provider billing cap. Call/token limits are enforced; tokenization, pricing or availability changes require recalculation before running. No retries/cache/batch/tools are configured. Repeated invocations are separate runs and require the approved budget to cover them.

Successful live calls print SDK usage and synthetic generated responses for human rating; failures print a constant summary, not raw provider errors. Latency and every failed fixture are recorded. Failed calls may be billed without returned usage: reconcile provider usage privately before stating total cost. Redact reports before posting. No model availability was tested against this account.

Before #22 can be unlocked, a human must review a capped, approved live report containing:

1. Every fixture outcome, latency, usage and reconciled cost; rejected malformed/unknown references count as reported failures, not hidden successes.
2. Zero accepted nonexistent asset references and no fabricated unseen motion, soundtrack or whole-film quality claims. Exact ID/quote validation alone is insufficient.
3. At least three distinct cases with author/rater evidence of useful grounded decisions, including consented work appropriate to the intended feature. Identify who rated, their interpretation, failure cases and limitations without exposing private work.
4. A reviewed go/narrow/stop decision. Thresholds are directional evidence, not statistical proof. Issue #22 remains blocked until that review.
